# Architecture

## The network

Lexnet (`model/`) is a per-byte sequence tagger with float64 weights, generated by hand rather
than trained. Its shape, read from `lexnet_weights.bin`:

| part | size |
| --- | --- |
| embedding | 128 x 14: 13 indicator features per byte plus a 6-bit character code; bytes >= 128 map to a null row |
| forward cell | 6 layers, 18 recurrent state units (`C L S Q P E sf star_in closed Sclose Qclose ls bsP W N d h1 h2`) |
| backward cell | 2 layers, 7 recurrent state units (`W copen2 lps kwc tyc cst fnc`) |
| head | 11 logits, argmax (lowest id wins ties) |

Every layer is `clip(W v + b, 0, hi)` followed by a parameter-free concatenation of carried units.
`hi` is 1 for logic units, 14 for the word-length counter `d`, and infinity for the two hash
accumulators `h1`, `h2`. All inputs are 0/1 (or small integers), all weights are integers or
multiples of 2^49, so every value the network ever computes is an exact integer in float64.
That is what makes an exact transcription possible: no rounding anywhere.

The forward pass runs left to right and emits 15 bits per byte; the backward pass runs right to
left over those bits and the head classifies. The model ships `lexnet_kernel.h`, a C kernel
generated from the architecture, which is the reference we compare against.

## The program

The forward cell is a lexer state machine:

- **modes**: block comment `C`, line comment `L`, string `S`, char literal `Q`, with their
  open/close helper units (`sf` "slash first", `star_in`, `closed`, `Sclose`, `Qclose`, escape `E`);
- **preprocessor** `P` with line-start detection `ls` and backslash continuation `bsP`;
- **word** `W` and **pp-number** `N`, the counter `d` (14 minus the index in the word) and the
  accumulators `h1` (base-64 hash of word bytes 0..7) and `h2` (bytes 8..13);
- **keyword tables**: layers 3-5 compare `h1`/`h2` with the hashes of 74 words and emit `KW`,
  `TY`, `CONST`.

The backward cell propagates the word class from the last byte of a word to all of its bytes
(`kwc`, `tyc`, `cst`), detects function names via "a `(` follows after spaces" (`lps`, `fnc`),
and marks the first `/` of a comment opener via the next byte's `copen2`. The head is a
priority encoder: string > char > comment > preprocessor > keyword > type > function >
number > identifier > punctuation > whitespace.

`docs/network-to-logic.md` has the gate-by-gate derivation.

## The two implementations

```
src/lexnet.h          API, class ids
src/lexnet_logic.c    the program, one function per cell, one line per unit
src/lexnet_fast.c     the same program as a block scanner
src/main.c            CLI
```

`lexnet_logic` mirrors the network: a forward loop producing 15 bits per byte into a buffer,
a backward loop over the buffer, the head. It exists to be read and to be the bridge between
the weights and the optimized version.

`lexnet_fast` keeps only what determines the output:

```
lexnet_fast
  while bytes remain:
    classify_block     NEON: 7 bitmasks for 64 bytes (alnum, digit, numc, space, nl, lparen, special)
    line-start bits    bit tricks: which bytes are "only whitespace since the last newline"
    paren-ahead bits   bit tricks: which bytes are followed, after spaces, by '('
    scan_events        ctz loop over word starts and span openers:
                         word   -> perfect-hash keyword lookup, override bits
                         number -> override bits
                         " ' /  -> open_span: scan_quoted / scan_block_comment / memchr
                         #      -> preprocessor line (scan_preproc) if at line start
    paint_block        NEON: base classes from the masks, then the override bits
    span fill          memset of the comment / literal that ended the block, if any
```

Spans (comments, literals, preprocessor lines) are scanned by dedicated routines that run at
memory bandwidth; the next block starts where the span ends. The only state carried across
blocks is the position and the line-start flag; the preprocessor flag is consumed inside
`scan_preproc`.

## Tests and benchmarks

`tests/difftest.c` includes the original `lexnet.c` (with its `main` renamed) so the reference
kernel, the float64 interpreter, `lexnet_logic` and `lexnet_fast` run in one process on the
same inputs. `bench/bench.sh` times the two reference modes and both implementations.
See `docs/testing.md`.
